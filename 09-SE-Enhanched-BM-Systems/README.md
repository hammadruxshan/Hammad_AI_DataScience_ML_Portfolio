# 09 - Şölen Enhanced Business Management System
## Abstract

This project focuses on analysing and enhancing the existing business and software operations of Şölen, a Turkish confectionery company specialising in chocolate, sweets, snacks, children’s products, and gift items. Although Şölen has an established international presence, the project identified several system-level weaknesses affecting its efficiency, customer experience, and future growth potential.

The main issues identified were the lack of an e-commerce system, limited customer feedback channels, inefficient product delivery tracking, and manual inventory management, particularly around goods with expiry dates. To address these issues, the project proposed an enhanced business management system integrating e-commerce, real-time GPS delivery tracking, AI-supported customer communication, automated inventory management, and cloud-based system architecture.

The proposed system was designed using software engineering principles, including system requirements, functional and non-functional requirements, architectural design, UML use case diagrams, UML class diagrams, and UML object diagrams. AWS was selected as the proposed cloud platform due to its scalability, security, real-time data capabilities, and cost-effectiveness.

This project demonstrates software analysis, business problem-solving, system design, cloud architecture planning, logistics optimisation, and the application of technology to improve operational efficiency and customer satisfaction.

## Problem Statement

Şölen’s existing system faced several operational and digital limitations that could restrict business growth and customer satisfaction.

The key problems identified were:

Lack of a proper e-commerce platform, causing customers to rely on outdated phone-based ordering methods.
Lack of a structured feedback and communication channel for customers.
Difficulty tracking drivers and updating customers on delivery status.
Manual management of goods and inventory, creating risks around expiry dates, stock errors, product waste, and customer dissatisfaction.

These challenges could lead to missed sales opportunities, inefficient delivery operations, poor customer communication, product losses, and reduced competitiveness in a market increasingly shaped by digital commerce and automation.

Objectives
- To analyse the weaknesses of Şölen’s existing business and software system.
- To propose an enhanced system that supports e-commerce, delivery tracking, inventory management, and customer communication.
- To design a real-time GPS-based tracking solution for logistics and delivery monitoring.
- To propose an AI-supported chatbot and feedback system for customer service.
- To design an automated inventory management system using expiry tracking and FEFO principles.
- To define functional and non-functional system requirements.
- To propose a scalable AWS-based architecture for the enhanced system.
- To create UML use case, class, and object diagrams to represent system behaviour and structure.

## Methodology
1. Business Background Analysis
The project began by studying Şölen’s business background, product offering, international presence, and operational challenges.
2. Problem Identification
Key problems were identified in the areas of e-commerce, feedback channels, product delivery, and manual goods management.
3. Requirements Gathering
Requirements were gathered through research and interview-based analysis to understand the company’s current processes, system needs, and operational gaps.
4. Solution Design
Four major solutions were proposed: GPS delivery tracking, AI-supported feedback system, e-commerce platform integration, and automated inventory management.
5. System Requirements Definition
Functional requirements were defined for tracking services, sales tracking, and inventory management. Non-functional requirements included performance, scalability, safety, maintainability, and ease of use.
6. Architecture Design
AWS was selected as the proposed cloud platform due to scalability, real-time communication support, data security, route management capabilities, inventory optimisation, and cost-effectiveness.
7. System Analysis and Design
UML use case diagrams were created to compare the legacy system with the enhanced system. Class diagrams and object diagrams were used to represent system structure and real-world operational scenarios.
8. Business Viability and Social Impact Analysis
The proposed system was evaluated in terms of commercial feasibility, operational impact, customer satisfaction, efficiency, and long-term competitiveness.
9. Future Enhancement Planning
Future improvements were proposed, including blockchain, AI, IoT, cloud computing, modular architecture, and additional scalability improvements.

## Proposed System Features
1. GPS Delivery Tracking

The enhanced system proposes GPS-based tracking for delivery vehicles. This allows managers and customers to monitor delivery progress in real time. The system can adjust estimated arrival times based on traffic, road risks, weather, and other delays.

Key features include:

Real-time driver location tracking.
Estimated time of arrival updates.
Route optimisation.
Delivery checkpoint tracking.
Manager notifications.
Proof of delivery.
Role-based access for customers, managers, and delivery personnel.

2. AI-Supported Customer Communication and Feedback

The system proposes an AI-supported chatbot that allows customers to communicate with the company, track parcels, ask questions, and submit feedback.

Key features include:

AI chatbot support.
Delivery code or email-based parcel tracking.
Customer feedback submission.
Complaint categorisation.
Email notifications.
Staff dashboard notifications.
Customer service improvement through feedback analysis.

3. E-Commerce Integration

The project proposes integrating an online store into Şölen’s website, allowing customers to browse products, view prices, and make purchases online.

Key features include:

Online product catalogue.
B2B and B2C ordering support.
Shopping cart and checkout process.
Product search and filtering.
Order confirmation and tracking.
Wider customer accessibility.
Improved brand visibility.

4. Automated Inventory Management

The inventory management system focuses on tracking stock levels, product movement, and expiry dates to reduce waste and prevent goods with short shelf lives from being delivered to customers.

Key features include:

Real-time inventory tracking.
Expiry date monitoring.
FEFO: First-Expired, First-Out stock handling.
Automated alerts for products nearing expiry.
Stock level monitoring.
Automated purchase order generation.
Reduced human error in manual inventory management.
## Functional Requirements
Tracking Service: Create and manage orders, track orders in real time, and create delivery schedules with route optimisation.
Sales Tracking Service: Capture sales orders and invoices electronically, track sales performance by product and customer, and support sales reporting.
Inventory Management Service: Track inventory levels in real time, monitor product movement, and generate automated purchase orders based on stock levels.
## Non-Functional Requirements
Performance: The system should be responsive and able to handle high traffic volumes.
Scalability: The system should be able to grow with increasing business demand.
System Safety: The system should protect user data and prevent unauthorised access.
Maintainability: The system should be easy to update and maintain.
Ease of Use: The system should be easy to navigate for customers, staff, managers, and delivery personnel.
## System Architecture

The proposed Şölen Enhanced System uses AWS as the operational cloud platform. The architecture includes authentication, API gateway access, load balancing, and separate service modules for shipment GPS tracking, inventory management, and customer service.

The system includes the following modules:

GPS Integration Module
Real-Time Tracking System Module
Inventory Management System Module
Customer Service Module
Authentication and Authorisation Layer
API Gateway
Load Balancer
Service Databases
Centralised Storage

AWS was selected because it supports scalability, real-time collaboration, data security, route management, inventory optimisation, and pay-as-you-go cost efficiency.

## Limitations
The project was a system design and proposal rather than a fully implemented software application.
Some features, such as the AI chatbot and GPS route optimisation, were conceptual and not developed into working prototypes.
The AWS architecture was proposed at a design level rather than deployed in a live cloud environment.
The inventory system logic was described conceptually and would need implementation and testing.
Real user testing with customers, drivers, managers, and warehouse staff was not conducted.
Cost estimates, security testing, and operational deployment planning would need further detail for real-world implementation.
